# Stage 1 design: data layer and access model

Contract for stage 1 of the fleet adoption (`docs/fleet-audit-2026-10-21.md`). It replaces the five
legacy global classes (`block_download_certificates_controller`, `_access`, `_query`, `_retriever`,
`_packager`) with namespaced classes under `classes/local/`, and closes S1-S8, S13, D1-D19 and P9.
The entry points keep their URLs and request parameters (stage 2 replaces the AJAX scripts with
external functions, stage 3 the rendering); only what they call changes.

Two passes, each one commit:

- **1a, library**: the classes below and their PHPUnit tests. Nothing calls them yet.
- **1b, rewiring**: every entry point, both tasks and the block call the library; the legacy
  classes are deleted; dropped sources disappear from every path.

## Owner decisions this stage implements

- Sources: `tool_certificate` and `mod_customcert` only.
- Teachers: a course capability, `block/download_certificates:downloadcourse` (`CONTEXT_COURSE`,
  archetypes `editingteacher` and `teacher`, `RISK_PERSONAL`), checked in each course context, with
  core's group rules and active enrolments only.
- The block can stand on the dashboard, the front page, a course page and a user profile; the scope
  narrows to the course or the profile user there (the rendering is stage 3; the scope API is here).

## Classes

### `local\source\source` (abstract) and its two implementations

`local\source\tool_certificate`, `local\source\customcert`. One object per certificate plugin; the
only place that knows its tables, columns and how its PDF is obtained.

- `get_type(): string` — `'tool_certificate'` or `'customcert'`; the value stored in task filters
  and in the `type` column of the union.
- `is_available(): bool` — the plugin is installed (`core_plugin_manager` reports it, its issue
  table exists and the classes the PDF path needs exist). Unavailable sources contribute nothing
  and raise nothing.
- `get_issue_sql(): array` — `[$sql, $params]` of one SELECT returning exactly these columns, the
  same in both sources so the two can be `UNION ALL`ed without casts: `uniqueid` (char, `type`
  prefix + issue id, e.g. `tc_12`), `issueid` (int), `type` (char literal), `userid`, `courseid`
  (0 when the issue has no course), `coursename` (course full name or `''`), `templatename`,
  `code`, `timecreated`. No `COLLATE`, no `CAST`. Deleted users excluded (`u.deleted = 0`).
- `get_issue(int $issueid): ?\stdClass` — one row in the same shape.
- `get_content(\stdClass $issue): \stored_file|string` — the PDF. tool_certificate: its stored issue
  file (read the plugin's own code for the file area and item id; no guessing loops, no HTTP).
  customcert: generated by the plugin's template class for that user, guarded by `class_exists()`.
  Throws `\moodle_exception` when there is no PDF.
- `get_filename(\stdClass $issue): string` — `<fullname>_<template>_<code>.pdf` through
  `clean_filename()`, without the directory.

`local\source\registry::get_available(): source[]` keyed by type; the one list every caller
iterates.

### `local\scope`

Who may see which certificates, expressed as SQL so a large course never becomes a placeholder
list (PostgreSQL stops at 65535).

- `scope::for_user(int $userid, ?int $courseid = null, ?int $profileuserid = null): scope`.
  - The user's own certificates are always in scope.
  - A user with `:manage` in the system context sees every certificate (narrowed by the optional
    course or profile user).
  - Otherwise, for each course where the user holds `:downloadcourse` and could enter the course
    the way `require_login()` decides it (an active enrolment, or `moodle/course:view` there) —
    never `SITEID`: if the
    course's effective group mode is `SEPARATEGROUPS` and the user lacks
    `moodle/site:accessallgroups` there, the members of the user's groups in that course who are
    actively enrolled; else every actively enrolled user (`get_enrolled_sql(..., onlyactive=true)`).
    A teacher with separate groups and no group sees nobody but themself.
  - `$courseid` keeps that course only; `$profileuserid` keeps that user only.
  - The group rule reads the course's group mode, not a certificate activity's: certificates are
    downloaded per course, so a customcert activity set to separate groups inside a course with no
    group mode is not narrowed (owner decision, 2026-10-22).
- `get_sql(string $useridcol, string $courseidcol): array` — `[$where, $params]` to AND into a query
  over the union; unique placeholder names per call (`\core\dml\...` helpers or a running counter
  with a separator — never `prefix . $n . $m`).
- `is_manager(): bool`, `get_course_ids(): int[]` (courses with `:downloadcourse`, for menus),
  `can_see(int $userid, int $courseid): bool` (single-download check, same rules).

### `local\repository`

Every read of certificates: search table, counts, menus, single downloads, ZIP lists.

- `filter` value object (`local\filter`): `courseid`, `userid`, `cohortid`, `datefrom`, `dateto`
  (half-open `[from, to)`, timestamps computed by the caller in the user's time zone), `search`
  (matched against `fullname` built by `$DB->sql_fullname()`, e-mail, course name, template name,
  code, with `sql_like` and unique placeholders). `filter::from_array(array): filter` cleans every
  key with `clean_param()` and drops unknown keys (S13).
- `search(scope, filter, string $sort, string $order, int $offset, int $limit): array` — sort
  allowlist; `uniqueid` appended as the tie-breaker (D16).
- `count(scope, filter): int`.
- `list_issue_refs(scope, filter): array` — `[type, issueid]` pairs in a stable order (`timecreated`,
  then `uniqueid`); what ZIPs are built from.
- `get_courses(scope): array`, `get_users(scope): array`, `get_cohorts(scope): array` — menus with
  counts, one aggregated query each (no per-row queries; D17), cohort names formatted in the
  cohort's own context.
- `get_issue_for_download(scope, string $type, int $issueid): \stdClass` — throws
  `required_capability_exception`-style `\moodle_exception('accessdenied')` when the issue is outside
  the scope (S3, S4, D15: no redirect to the other plugin's page).

### `local\zip_builder`

- `add(source, \stdClass $issue)` writes the PDF into the archive: a stored file through
  `copy_content_to_temp()` + `ZipArchive::addFile()`; a string through `addFromString()`. Entry
  names deduplicated with a keyed array (`name.pdf`, `name (2).pdf`; D22). Directory per source
  type inside the archive.
- `build(array $refs, string $zippath, ?callable $progress = null): array` — returns the per-issue
  errors (localised, no exception text from SQL); a failure on one issue never stops the others,
  and is written to `errors.txt` inside the archive.

### Request path (`local\download`)

- `send_zip(scope, filter, string $filename)` — refuses with a localised message when
  `count() > download::SYNC_LIMIT` (30, the threshold the async UI already uses); otherwise builds in
  `make_request_directory()` and sends with `send_temp_file()` (S8, D7).
- `send_single(scope, string $type, int $issueid)` — `send_stored_file()` for a stored file,
  `send_file($content, $name, 0, 0, true, true, 'application/pdf')` for a generated one.

### Background path

- The task row keeps `userid`, `type` and the cleaned filter JSON in `params`. The adhoc task builds
  `scope::for_user($task->userid, ...)` when it runs, never trusting the request (S1, D20). If the
  user is deleted, suspended or the scope is empty, the task fails with a localised error.
- On its first run the task freezes `list_issue_refs()` into `refs.json` in the task directory
  `make_temp_directory('block_download_certificates/tasks/' . $taskid)` and stores `total`; later
  batches read the frozen list by `batchoffset` (D9). The ZIP lives in the same directory (S2).
- `cleanup_expired`: removes the directory of every task it deletes or fails, fails `pending` and
  `processing` tasks stuck for 2 hours, deletes rows 7 days old; never touches a path outside
  `block_download_certificates/tasks/` (P9).
- The ZIP download script serves the file with `send_temp_file()` after checking owner and status,
  and marks the task `expired`. The hand-over re-runs the request-level check (`request::check_zip()`
  for the owner as they are now), not each certificate: the archive was built within the scope of
  that time and lives at most `cleanup_expired::READY_FOR`; accepted.

## Tests (PHPUnit, `tests/local/...`)

Both sources need their plugins in the runner (`mdl ci` installs them through moodle-dev `deps/`);
each test class skips with `markTestSkipped()` when its source is unavailable, so a missing plugin
shows as skipped, never as green.

- scope: manager; teacher with no groups; separate groups with and without
  `accessallgroups`; visible groups; a teacher in a group of course A seeing a student who is also in
  course B; suspended student enrolment and disabled instance excluded; a teacher whose own enrolment
  is suspended loses the course; a category manager with `moodle/course:view` keeps it; `SITEID` never in scope; course and
  profile narrowing; placeholders unique across two `get_sql()` calls in one query.
- repository: search and count agree for every filter; sort tie-breaker; date range half-open;
  deleted users excluded; `filter::from_array()` drops unknown keys and casts.
- single download outside the scope throws; inside works for both sources.
- zip_builder: dedupe of entry names; one failing issue leaves the others in the archive and an
  `errors.txt` line.
- task: frozen list survives a certificate issued between batches; per-task directory; a teacher
  who loses `:downloadcourse` between request and run gets a failed task; cleanup removes the
  directory and leaves another task's.
- Every guard above gets a mutation check before the stage closes (`mdl mutate --fast`).
